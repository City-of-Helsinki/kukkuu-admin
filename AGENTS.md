# Kukkuu Admin UI Agent Instructions

## Role

You are working on `kukkuu-admin`, the administrative and event management dashboard for the Kukkuu platform.

## Ecosystem

- **`kukkuu`**: The backend that provides the primary GraphQL API.
- **Target Audience**: Event organizers (external), system administrators, and product owners (internal).
  For the full architectural picture, see the [Service architecture](README.md#service-architecture) in the README and the backend's `ARCHITECTURE.md`.

## Commands

_Note: Always use `rtk` (Rust Token Killer) to prefix shell commands._

- **Install dependencies:** `pnpm install` (requires Node `>=24` and pnpm `11.5.3` via Corepack: `corepack enable`).
- **Run dev server:** `pnpm start` (runs on port 3001).
- **Build:** `pnpm build`.
- **Lint & Format:** `pnpm lint`, `pnpm format:code`.
- **Typecheck:** `pnpm typecheck` and `pnpm typecheck:e2e`.
- **Test (Unit):** `pnpm test` (Vitest).
- **Test (e2e):** `pnpm test:e2e` (uses Playwright. First run requires: `pnpm test:e2e:install`).
- **Generate GraphQL Types:** `pnpm generate:graphql`.

## Environments & Data

- **Env files:** Copy `.env.example` to `.env`. Optional `.env.local` can be used for a local backend. Key variable: `VITE_API_URI` points to the Kukkuu API. Note: `pnpm generate:graphql` reads `.env`, not `.env.local`.
- **Data Fetching:** Communicates exclusively with the Kukkuu backend via GraphQL.

## Domain Logic

- **Project Selection & Privileges**: In the site header's top right corner, the project selector lists projects based on user privileges. If a user lacks privileges for a project, it is not listed. Privileges can be partial (e.g., an organizer can create events but not publish them).
- **Events & Event Groups**: Event organizers can create new events and event groups. One event group can contain multiple events. Both an event group and an event always belong to exactly one project.
- **Enrollment Limits**:
  - A project configuration defines how many times a child can enrol per year (usually twice).
  - A child can participate in only **one** event per event group. If only one event group is published (e.g., for a spring season), a child can participate only once during that season since all available events fall under that single group.
- **Visibility Rules (Events vs Enrolments)**:
  - Published events and occurrences remain globally visible so the public UI and other event organizers can view them.
  - Unpublished events and occurrences are strictly isolated. Only system administrators and users who are members of the event's designated organisation can view or administer them.
  - Enrolment and attendee data are **never** globally visible, regardless of the event's publish state. Only system administrators and members of the event's organisation can access them.

## Rules and Guardrails

- **Authentication:** Login flows use Helsinki Profile (for external organizers) and city AD (for staff) via OIDC (Keycloak). Local login requires a user granted privileges in the backend (see "Authorizing login" in the README).
- **Generated Files:** `src/domain/api/generatedTypes/graphql.tsx` is generated by `pnpm generate:graphql`. Never hand-edit it.
- **Commits:** Must follow Conventional Commits. Husky `commit-msg` runs `commitlint`.
- **Hooks:** Husky `pre-commit` runs `doctoc` and `lint-staged`.
- **Release Management:** The version, `CHANGELOG.md`, and `.release-please-manifest.json` are owned by `release-please`. Do not edit them.

## Cross-Repo Impact Checklist

If there has been a change in the backend's GraphQL schema:

1. Ensure the local backend is running with the new schema and update `.env`.
2. Run `pnpm generate:graphql` here.
3. Run `pnpm typecheck` and tests to verify the admin dashboard still works.
